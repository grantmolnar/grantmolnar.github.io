# Adventure Reference Library Phase 6 Corpus Audit

## Purpose

This audit tests the completed reference workflow against representative bundled adventures. It asks a
narrow question: does one canonical record remove fragmented retrieval or materially improve table use
without flattening encounter voice, replacing specialized operating ledgers, or promoting every proper
noun into a dossier?

The sample deliberately contrasts a political court, a large location-driven dungeon, a heist whose
specialized ledgers already centralize operations, and a compact civic investigation. The retained
records were authored through the canonical revision-aware command path and then exercised in Author,
Play, generated packets, relocation, standalone export, and journal archives.

This document records the selective Phase 6 fixture boundary, not the current final corpus. The later
adventure-by-adventure defragmentation workstream may supersede a deferral or rejection when the completed
source demonstrates a stable canonical core. Current Aurelune decisions are recorded in
`docs/adventure-reference-defragmentation-roadmap.md` and the current corpus tests.

## Retention method

Each candidate had to satisfy all five Phase 6 tests:

1. recur across encounters or remain globally useful during play;
2. own a meaningful canonical core that should be edited once;
3. leave scene-specific action, clues, and changing state in encounter prose or link context;
4. improve Author search, Play retrieval, pinning, or generated sheets; and
5. preserve the adventure's established voice and operating language.

A specialized ledger remains preferable when the GM needs a dense matrix of changing relationships,
procedural state, or many comparable actors. A reference is a stable dossier, not a replacement for an
adventure-specific control surface.

## Complete-workflow observations

### Author

The unified library remains small enough to scan: two records in Aurelune, one in Harrowgate, and none in
the two restrained samples. Kind filters are useful without becoming separate silos. Aliases find formal
and table-short names, while derived backlinks make the scope of each record visible before editing or
removal. The records do not reproduce the Court Ledger, Dungeon State, or heist matrices.

### Play

Linked cards preserve encounter-authored order. At the Argent Canopy, Theron appears before the Sunseed
because procedure is established before the relic's local stakes are summarized. Encounter-local context
answers “why is this dossier relevant here?” without moving scene action into canonical prose. Full
reference panels, global search, and typed pins create no visit, note, consequence, focus change, or other
journal operation.

The reference-light sample presents a small explicit empty state rather than an unfinished-looking
library. That result is important evidence: the feature remains optional when encounter prose and a
compact route already make retrieval easy.

### Generated packet

Populated samples now publish a grouped `references/index.md` and UUID-named sheets. Encounter sheets
retain authored link order and local context. Reference sheets derive backlinks in encounter order. The
Cauldron and *When the Swine Kneel* omit the reference namespace entirely. Generated files are evidence
of the source records, not a second editable corpus.

### Portability

Aurelune's two UUIDs and every contextual link survive canonical relocation, clean standalone export,
and an immutable journal archive snapshot. No campaign identifiers, cross-adventure matches, calendar
coordinates, or synchronization fields enter the adventure source. This preserves the later campaign
model in which campaign-owned entities bind explicitly to portable adventure-local references.

## Source-data changes versus generated output

The authoritative changes are limited to:

- two reference records and thirteen encounter links in *The Concord of Aurelune*;
- one reference record and eight encounter links in *The Bell Beneath Harrowgate*; and
- this audit plus the documentation and tests that define the retention boundary.

Checked-in generated packets were refreshed because the bundled-example regression suite treats them as
reproducible published examples. Their new reference files and linked-reference sections are derived
output and must not be edited independently.

No encounter introduction, clue, revelation, journal event, operating ledger, or voice-audit conclusion
was rewritten. Local repetition was intentionally retained where it supplies scene framing, dialogue,
immediate procedure, or a changing state rather than merely restating the canonical core.

## Phase 6 conclusion

The evidence supports a deliberately sparse corpus policy:

- use references for a recurring subject whose stable core is otherwise fragmented across several
  encounters;
- use link context for the local role of that subject;
- keep scene voice and changing state in encounters;
- keep dense comparison and state matrices in specialized ledgers; and
- leave compact adventures reference-light when the dossier would only restate the premise.

Phase 6 therefore retains three records across two adventures, leaves two sampled adventures
reference-light, and introduces no schema, journal, campaign, or calendar expansion.
